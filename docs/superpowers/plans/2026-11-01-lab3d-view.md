# 3D Lab View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a "Lab 3D" card next to the 2D floor plan in the HTML report, rendering the workcell in the control room style. It is driven by the trace and kept in sync with playback.

**Architecture:**
- **`lab3d_model.js`:** a pure model with no DOM and no THREE. It provides the layout, the instruction timeline rebuilt from the run's blocks, and `stateAt(t)`.
  - Node runs it from pytest, so the logic is tested in Python's runner.
- **`lab3d.js`:** draws the model with a vendored three.js r128.
- **`report.js`:** creates the card and calls `Lab3D.update(t)` from `setTime`.
- **`build.py`:** inlines the three new scripts and adds `reach` to the instrument data.

**Tech Stack:** Python 3.14, pytest, three.js r128 (UMD build, global `THREE`, MIT), Node (only to test the pure model; tests skip without it).

**Spec:** `docs/superpowers/specs/2026-11-01-lab3d-view-design.md`

## Global Constraints

- The report stays self-contained. No `src=`/`href=` network URLs: `test_self_contained` must keep passing.
- The data contract grows only by `reach` (list or null) on each `instruments[]` entry.
- **Accuracy:** the drawing must follow these rules.
  - A move animates over exactly `[start, start + duration)`.
  - The plate is at `src` before the move, in the gripper during it, and at `dst` after it.
  - An instrument glows only while a non-move instruction with duration > 0 runs on it.
  - Handoff, storage and hotel never glow.
  - Nothing moves after `run.alarm.time`.
- The live speed menu becomes `[1, 2, 5, 10, 30, 60, 120, 300, 600]`; the default stays 60.
- **Themes:**
  - Light: background `#eef3f8`, grid `#b9c9db`/`#d3deea`, edges `#2b5d93`, arm `#0a8fd0`, run `#00a6d6`.
  - Dark: background `#070b12`, grid `#14304d`/`#0f2238`, edges `#2a6fb0`, arm `#47e0ff`, run `#47e0ff`.
  - The view follows `prefers-color-scheme` and switches live.
- Plate colours: owned plates use `wfColor(workflow index)`; borrowed/shared plates are neutral grey.
- **Rendering:** the scene is built lazily, the first time the card is visible.
  - It renders only when t, the camera, the theme or the size changes.
  - It does not render while the card is off screen.

## Review Focus

1. **Switching mode tabs mid-playback:** the scene shows the new run's plates and timeline, with nothing left over from the old run. Covered by the Task 4 browser check, which switches tabs.
2. **A run with no blocks** (`no_solution`) or a deadlock: the card shows the workcell idle and throws no errors. Covered by `test_state_empty_run`.
3. **A v1 single-arm workcell** (an arm with `reach: null`, times in "min"): the layout puts everything in one ring the arm can reach. Covered by `test_layout_single_arm`.
4. **Nest ids with suffixes** (`stamp1.src`, `lh1.dst`): the plate is drawn on the owning instrument. Covered by `test_state_nest_suffix`.
5. **Scrubbing backwards:** the state is recomputed from t alone, with no accumulated drift. Covered by `test_state_is_pure`.

### Task 2: Timeline and state at t (`lab3d_model.js`)

**Files:**
- Modify: `workcell/report/lab3d_model.js`
- Create: `tests/test_lab3d.py`; the node harness lives inside it as a string run with `node -e`, and the whole module is skipped if `shutil.which("node")` is None.

**Interfaces:**
- **Module export:** UMD-style. It sets `module.exports` when `module` exists, and sets `window.Lab3DModel` otherwise.
- **`timeline(run, instruments) -> {instr, moves, T}`:**
  - `instr` is a list of `{t0, t1, block, instrument, op, args}`, sorted by `t0`. It is rebuilt from each block's `start` plus the cumulative `duration`s of its `instructions`.
  - `moves` is the subset with `op === "move"`, with the added fields `arm`, `plate`, `src`, `dst` and `srcInst`/`dstInst` (the nest owners).
  - `T` is the end time of the last instruction.
  - When `run.alarm` is set, any instruction starting at or after `alarm.time` is dropped, and `t1` is clipped to `alarm.time`.
- **`nestOwner(instruments) -> {nestId: instrumentId}`.**
- **`stateAt(tl, initialLocations, t) -> {plates, arms, busy}`:**
  - `plates`: `{plate: {at: nestId}}` or `{plate: {arm, src, dst, u}}`, where `0 ≤ u < 1`.
  - `arms`: `{arm: {plate, src, dst, u}}`, for arms with a move in flight.
  - `busy`: a `Set` of instrument ids running a non-move instruction with `t1 > t0`, over `t0 ≤ t < t1`.
  - It is pure: it depends only on its arguments.

- [ ] **Step 1: Write failing tests** in `tests/test_lab3d.py`. They use a module fixture that runs `run_live` on `examples/libprep_2arm.yaml` and `examples/libprep_capture.py` with seed 0, then takes `report_data` of it. A helper `js(expr, data)` runs node, loads the model, binds `D = data`, and prints `JSON.stringify(expr)`.
  - `test_timeline_matches_trace`: the `[t0, instrument, op]` triples from `timeline` equal `[(e.time, e.instrument, e.op) for e in trace.events]`, sorted the same way.
  - `test_state_carried_plate`: for the first move `m`:
    - at `m.t0 - 1` (if that's ≥ 0) the plate is `at` its src
    - at `(m.t0 + m.t1) / 2` it is carried by `m.arm` with `0 < u < 1`
    - at `m.t1` it is `at` dst
  - `test_state_busy`: one test, three checks.

    - No handoff, storage or hotel is ever busy at any instruction's midpoint.

  - `test_state_alarm_truncates`: a synthetic run with one block (two 10 s instructions from t=0) and `alarm.time = 5`. Its `timeline` has one instruction with `t1 = 5`.
  - `test_state_empty_run`: for `{blocks: [], alarm: null}`, `T = 0`, and `stateAt` puts every plate at its initial location.
  - `test_state_is_pure`: `stateAt` at t=500 after evaluating t=900 equals `stateAt` at t=500 evaluated fresh.

### Task 3: Layout (`lab3d_model.js`)

**Files:**
- Modify: `workcell/report/lab3d_model.js`, `tests/test_lab3d.py`

**Interfaces:**
- **`layout(instruments) -> {pos, arms, groups}`:**
  - `pos`: `{id: [x, z]}` for every instrument that isn't an arm.
  - `arms`: `{id: {at: [x, z], link}}`. The arm's two equal links have length `link`, so it reaches `2 * link`.
  - `groups`: a list of lists of ids.
- **Groups** are the connected components of arms and the instruments they reach. An arm whose `reach` is null reaches every instrument that isn't an arm.
- **Placement:**
  - Within a group, the arms sit in a row along x, in the order of a BFS along their shared handoffs.
  - A handoff sits at the mean position of its arms.
  - Each arm's other instruments go on an arc of 1.45π radians, centred on the direction away from that arm's handoffs (any direction if it has none).
  - The radius is `max(2.3, 0.95 * n / (1.45π))`, and `link = 0.55 * radius`.
  - Groups are stacked along z with a gap of 2 units between them.

- [ ] **Step 1: Write failing tests:**
  - `test_layout_two_arm`: on libprep_2arm (instruments taken from report_data):
    - every instrument except the arms has a `pos`
    - `ho1` is equidistant (±0.01) from `arm1` and `arm2`
    - every instrument an arm reaches lies within `2 * link` of it
    - no two `pos` are closer than 0.9
  - `test_layout_single_arm`: on `workcell_small`, everything is placed and reachable by the one arm.
  - `test_layout_separate_lines`: on `examples/libprep_10k.yaml` (load it with `load_workcell` and build instrument dicts the same way as `report_data`):
    - there are 4 groups
    - the bounding boxes of the groups don't overlap

### Task 4: Renderer and report wiring

**Files:**
- Modify: `workcell/report/lab3d.js`, `workcell/report/report.js`, `workcell/report/template.html`, `workcell/report/report.css`
- Test: `tests/test_report.py`, plus a browser check

**Interfaces:**
- Consumes: `Lab3DModel.layout`, `timeline`, `stateAt` and `nestOwner` (Tasks 2–3); the `THREE` global.
- **`window.Lab3D.create(el, {instruments, workflows, plateColor(plate) -> css color}) -> view`.** The view has:
  - `setRun(run)`: rebuilds the plates and the timeline; the instrument meshes are kept.
  - `update(t)`: poses the arms, plates and glow for time t, and requests one frame.
  - It renders only when there is a change and the card is on screen (an `IntersectionObserver`).
  - It handles orbit by pointer drag and zoom by wheel or pinch.
  - It listens to `matchMedia("(prefers-color-scheme: dark)")` and recolours the scene live.
  - It fits the camera to the bounds of the layout when first shown.
  - Instrument ids are drawn as canvas-texture sprites whose opacity fades with camera distance.
  - A plate in the gripper leaves a trail: the last 0.6 s of screen time, fading.
  - A plate in a closed instrument (thermocycler, centrifuge, vacuum_concentrator, plate_reader, plate_sealer, plate_peeler) is hidden.
  - Plates on storage/hotel are drawn as a short stack, up to 6 visible; the instrument label shows the count.
- **Template:** a new card `<div class="card" id="card-lab3d"><div class="card-h"><h2>Lab 3D</h2><span class="muted small">drag to orbit, scroll to zoom</span></div><div id="lab3d" class="lab3d"></div></div>`.
  - It goes right after the Floor plan card.
  - The two cards are wrapped in `<div class="pair">`: a grid that is two columns at ≥ 1400px and one column below that.
  - `.lab3d` has `aspect-ratio: 4/3; max-width: 100%`.
- **`report.js`:**
  - Build the view lazily, when `#card-lab3d` first intersects.
  - Call `view.setRun(run)` wherever the run changes.
  - Call `view.update(S.t)` in `setTime`.
  - Live `SPEEDS = [1, 2, 5, 10, 30, 60, 120, 300, 600]`.
  - `plateColor` reuses the 2D floor plan's rule: owner workflow colour, or neutral for borrowed plates.
